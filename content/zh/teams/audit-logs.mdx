**审计日志**记录团队里发生过的关键操作:谁、在什么时候、对什么对象、做了什么、成功还是失败。入口在 **设置 → 审计日志**。

<Callout type="warning">
  **只有团队拥有者与管理员能查看审计日志。**成员和查看者打开会看到提示。
</Callout>

## 表格里的列

| 列 | 说明 |
| --- | --- |
| **操作** | 做了什么,如「邀请成员」「删除测评」「导出数据」 |
| **状态** | 成功 / 失败 |
| **操作人** | 谁做的。系统自动发起的操作(如到期清理、审核封禁)显示为**系统** |
| **对象** | 被操作的东西及其 ID 前缀 |
| **时间** | 发生时间 |

点击任意一行可以展开**详情**,不同操作带的字段不一样——比如导出会额外记录导出的数据类型(答卷 / 线索 / 答题者)和行数。

## 覆盖哪些操作

大致分这几类:

- **团队** —— 删除团队、转让所有权、套餐变更。
- **成员** —— 邀请、移除、离开、改角色、禁用 / 启用。
- **测评** —— 创建、更新、移入回收站、恢复、彻底删除、封禁 / 解封。
- **线索与答题者** —— 移入回收站、恢复、彻底删除。
- **连接** —— 创建、更新、删除。
- **凭证** —— API 密钥与 MCP 令牌的创建、吊销、恢复、删除。
- **用量** —— AI 消耗、邮件消耗、[数据导出](/zh/results/export)。

顶部可以按**操作类型**和**状态**筛选,便于回答「上周谁导过数据」这类问题。

<Callout type="info">
  日志是**只读**的,不能编辑或删除——能被改的审计日志没有意义。
</Callout>
