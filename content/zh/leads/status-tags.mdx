# 状态、标记与负责人

一条线索身上有三种互不干扰的标注:**跟进状态**(走到哪一步)、**标记**(是什么样的人)、**负责人**(归谁管)。

## 跟进状态

跟进状态是**单选**的,代表线索在管道里的位置。系统内置四档:

| 状态 | 典型含义 |
| --- | --- |
| **新线索** | 刚进来,还没人碰过 |
| **已联系** | 已经发过邮件或打过电话 |
| **已转化** | 成交了 |
| **无效** | 重复、测试数据、明显不匹配 |

内置状态**可以改名但不能删除**;此外可以自建状态、拖动排序。看板视图的列就是按这个顺序排的。

<Callout type="warning">
  删除一个自定义状态时,原本处在该状态的线索会被**重置回默认状态**。保存前弹窗会告诉你影响多少条。
</Callout>

## 标记

标记是**多选**的彩色标签,用来标注跟状态无关的横切特征,比如「高意向」「待回访」「VIP」。一条线索可以同时挂好几个标记。

标记与状态的分工:**状态回答「走到哪了」,标记回答「这是什么人」**。不要用标记模拟阶段,否则筛选时两套体系会打架。

<Callout type="warning">
  删除标记会**从所有线索上一并摘掉**它,保存前弹窗会告诉你影响多少处引用。
</Callout>

## 在哪里配置

状态与标记都在 **线索 → 线索设置** 里配置,分为「线索状态」和「线索标记」两段。

<Callout type="info">
  这两项**只有团队所有者(owner)能改**。其他成员打开设置是只读的,页面上会有提示。日常给线索打标记、改状态不受此限制,普通成员都能做。
</Callout>

## 负责人

负责人把线索指派给某个团队成员,回答「这条归谁跟」。

- 可指派的对象是团队里**在职的非只读成员**——[只读(viewer)角色](/zh/teams/members) 不能被指派。
- 单条线索在 [详情页](/zh/leads/detail) 的「跟进」区改;多条用列表视图的 [批量指派](/zh/leads/list-board#批量操作)。
- 每次变更都会写进线索的**动态**时间线,被指派人会收到通知。

负责人还会影响 [预约](/zh/bookings):开启预约审核后,由**线索负责人**确认对方的预约申请。

<Callout type="info">
  状态、标记、负责人的每一次变更都记录在 [线索详情](/zh/leads/detail#动态) 的动态里,包含谁在什么时候改的。
</Callout>
