# 触发事件与范围

每条连接自己决定**什么时候触发**(事件)和**哪些测评能触发它**(范围)。两者是「与」的关系:事件命中、且来源测评在范围内,才会投递。

## 触发事件

每条连接至少要选一个事件:

| 事件 | 什么时候触发 |
| --- | --- |
| **新增线索** | 一个人**第一次**向你的团队留下联系方式 |
| **新预约产生** | 有人约了一场会谈 |
| **预约被取消** | 任意一方取消了预约 |
| **预约被改期** | 预约换了时间 |

<Callout type="warning">
  **「新增线索」只在这个人第一次留资时触发一次。**同一个人之后再做别的测评,不会重复触发——因为线索是 [跨测评去重](/zh/leads#线索从哪来) 的。想要每次提交都通知,这不是你要的事件。
</Callout>

## 触发范围

范围决定哪些测评可以触发这条连接:

- **全部测评** —— 默认。团队里任何一张测评产生的事件都会投递。
- **指定测评** —— 只有选中的那几张测评才会触发。

<Callout type="info">
  范围按**事件来自哪张测评**判定。对「新增线索」而言,那是这个人**首次留资**的那张测评,不是他最近做的那张。
</Callout>

典型用法:主打的获客测评推 Slack 让团队立刻看到,内部用的小测评就别打扰大家了。

## 组合建议

| 想要的效果 | 事件 | 范围 |
| --- | --- | --- |
| 新客户进来时全员知道 | 新增线索 | 全部测评 |
| 只盯旗舰测评的线索 | 新增线索 | 指定测评 |
| 日程有变动时提醒自己 | 预约取消 + 预约改期 | 全部测评 |
| 把线索同步进邮件营销工具 | 新增线索 | 全部测评 |

<Callout type="info">
  改事件或范围**只影响之后发生的事件**,不会补发历史。
</Callout>
