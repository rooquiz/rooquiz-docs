---
title: 发信服务(SMTP)
---

[邮件渠道](/zh/connectors/channels#邮件)通过**你自己的 SMTP 服务器**发信 —— RooQuiz 不代发。所以通知是从你自己的地址发出的,也没有平台层面的发送量限制。

在**设置 → 组织 → 发信服务**里配一次,团队里所有邮件连接器共用这一份。

<Callout type="warning">
  没有**已验证**的发信服务时,邮件连接器仍然能保存,但一封都投不出去。它的卡片上会显示红色的「未配置发信服务」标记。
</Callout>

## 填什么

| 字段 | 说明 |
| --- | --- |
| **SMTP 服务器** | 服务商给的主机名,如 `smtp.gmail.com` |
| **端口** | `587`(STARTTLS)、`465`(SSL/TLS)或 `2525` |
| **用户名** | 通常是完整邮箱地址;部分服务商用固定字面量 |
| **密码** | SMTP 密码或 API key。以后修改其他字段时留空,就沿用已保存的那个 |
| **发件人地址** | 必须是这台 SMTP 服务器允许代发的地址 |
| **发件人名称** | 收件人看到的显示名 |
| **回复地址** | 选填,希望回复走别处时才用 |

<Callout type="info">
  **25 端口不能用。** 我们的托管平台封禁了该端口的出站连接,请用 587 或 465。
</Callout>

## 各服务商怎么填

<Tabs items={['Gmail', 'Resend', '企业自建邮箱']}>
  <Tab value="Gmail">
    | 字段 | 值 |
    | --- | --- |
    | SMTP 服务器 | `smtp.gmail.com` |
    | 端口 | `587 (STARTTLS)` |
    | 用户名 | 完整的 Gmail 地址 |
    | 密码 | **16 位应用专用密码** |
    | 发件人地址 | **同一个** Gmail 地址,或该账号里已验证的「以此身份发送」别名 |

    去 [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords) 生成应用专用密码。它只显示一次,格式是四组四位 —— 粘贴前**把空格去掉**。

    <Callout type="warning">
      账号密码是不行的。Google 已经关闭了邮件客户端的密码登录,只能用应用专用密码 —— 而应用专用密码只有在**两步验证已开启**时才存在。
    </Callout>

    如果那个页面显示「你要找的设置不适用于你的账号」,原因是三者之一:两步验证没开;这是 Google Workspace 账号且管理员禁用了应用专用密码;或者账号加入了高级保护计划(会直接禁掉这个功能)。

    另外 Gmail 有发送上限:个人账号约**每天 500 个收件人**,Workspace 约 **2000**。对团队通知完全够用,但不适合群发。
  </Tab>

  <Tab value="Resend">
    | 字段 | 值 |
    | --- | --- |
    | SMTP 服务器 | `smtp.resend.com` |
    | 端口 | `587 (STARTTLS)` |
    | 用户名 | `resend` —— 就是这个词本身 |
    | 密码 | 一个 Resend API key(`re_…`) |
    | 发件人地址 | 你在 Resend 里已验证域名下的任意地址 |

    如果你希望通知从**自己的品牌域名**发出、而不是某个私人邮箱,这是最省事的选择,也没有 Gmail 那种每日上限。
  </Tab>

  <Tab value="企业自建邮箱">
    向管理邮件系统的同事要 **SMTP 主机名、端口和凭据**。优先用 587 + STARTTLS,只有 465 可选时才用 465。

    两个常见坑:

    - 用户名往往是**完整邮箱地址**,不是 `@` 前面那截。
    - **发件人地址必须属于你自己的域名**。多数企业邮件服务器会拒绝代发声称来自其他域名的信。
  </Tab>
</Tabs>

## 保存并验证

<Steps>
### 填好字段,点「保存并验证」

保存和验证是同一个动作,所以不会出现「存下来了但没测过」的中间状态。

### 去收件箱找那封测试邮件

<Callout type="warning">
  测试邮件发往**你自己的 RooQuiz 账号邮箱** —— 也就是你当前登录用的那个,**不是**你刚填的发件人地址。如果没收到,先查那个邮箱和它的垃圾邮件文件夹,别急着改配置。
</Callout>

### 确认状态显示「已验证」
</Steps>

「已验证」的含义是:你的 SMTP 服务器接收了这封信并返回了成功码。这**不等于送达** —— SMTP 服务器是先收下、再往外转投,所以信件之后仍可能被判垃圾或被退回。如果验证通过却没收到,问题在收件一侧:先看垃圾邮件文件夹,再去发件邮箱里找退信。

## 验证失败时

页面上会**原样显示你的 SMTP 服务器返回的错误**,刻意不做转述,方便你直接照着处理。常见的几种:

| 错误 | 含义 |
| --- | --- |
| `535 Username and Password not accepted` | 凭据不对。Gmail 的情况通常是用了账号密码,或者应用专用密码里的空格没去掉 |
| `553 Sender address rejected: not owned by user` | 发件人地址不在这台服务器允许代发的范围里。改成该账号真正拥有的邮箱或别名 |
| `550 relay not permitted` | 服务器完全不为你转投 —— 一般是用户名填错,或该邮箱没开 SMTP 权限 |
| 超时 / 连接失败 | 主机名或端口不对,或者服务器不接受来自外网的连接 |

## 一些细节

- 密码保存后**不再回显**。修改其他字段时把它留空,已保存的密码不会被动。
- 改动服务器、端口、用户名、密码或发件人地址,状态会退回**未验证**,直到下一次验证成功。
- 保存与验证有**频率限制**,每个团队每小时只能试几次 —— 每一次都会真的连接你的服务器、真的发出一封信。
- **移除**发信服务会删掉已保存的密码。改配置不需要先移除,直接覆盖保存即可。只要还有**启用中**的邮件连接器,移除会被拒绝 —— 免得你把自己的投递静默弄坏。
- 如果之后某次投递永久失败(凭据失效、发件人地址被拒),状态会变成**验证失败**,邮件连接器会停止投递直到你修好。单个收件人地址失效**不会**导致这种情况,那只会让那一封信失败。
