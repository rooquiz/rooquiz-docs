團隊寄出的郵件——[郵件連接器](/zh-TW/connectors/channels#郵件)的通知，以及你發給作答者的郵件——都透過**你自己的寄信服務**發出。RooQuiz 不代發，所以信件是從你自己的位址寄出的。

在**設定 → 團隊 → 寄信服務**裡設定。只有團隊擁有者和管理員能管理寄信服務。

| 方案 | 每個團隊的寄信服務數 |
| --- | --- |
| **Free** | 1 個 |
| **Pro** | 最多 3 個 |

Gmail 帳號和 SMTP 伺服器共用同一組名額。之後每個郵件連接器在**寄信服務**裡選用其中一個。

<Callout type="warning">
  沒有**已驗證**寄信服務的郵件連接器仍然能儲存，但一封都投不出去。它的卡片上會顯示紅色的「未設定寄信服務」標記。
</Callout>

## 方式一：連接 Gmail（用 Gmail 時推薦）

點**連接 Gmail**，在 Google 視窗裡同意授權即可。不用設定 SMTP，也**不需要應用專用密碼**——RooQuiz 只拿到寄信權限，讀不了你的收件匣。

- 每個 Gmail 帳號透過 RooQuiz **每天最多寄 500 封**。超出後，發給作答者的群發郵件會暫停，並在**隔天自動繼續**；連接器通知超出後則會失敗，直到隔天。
- **測試**會從這個 Gmail 帳號寄一封信到你自己的電子郵件。
- 如果狀態顯示**需要重新連接**，點**重新連接**並再次同意授權。
- 想用另一個 Gmail 位址寄信，就再連接一個 Gmail 帳號。

<Callout type="info">
  中斷連接會刪除 RooQuiz 對該 Gmail 帳號的存取權限。請先關閉正在使用它的郵件連接器。
</Callout>

## 方式二：新增 SMTP 伺服器

點**新增 SMTP 伺服器**，透過服務供應商的 SMTP 寄信——適合透過 Resend 等服務用品牌網域寄信，或使用公司自己的郵件伺服器。

### 填什麼

| 欄位 | 說明 |
| --- | --- |
| **SMTP 伺服器** | 服務供應商給的主機名稱，如 `smtp.gmail.com` |
| **通訊埠** | `587`（STARTTLS）、`465`（SSL/TLS）或 `2525` |
| **使用者名稱** | 通常是完整電子郵件位址；部分服務供應商用固定字面值 |
| **密碼** | SMTP 密碼或 API key。以後修改其他欄位時留空，就沿用已儲存的那個 |
| **寄件者位址** | 必須是這台 SMTP 伺服器允許代發的位址 |
| **寄件者名稱** | 收件人看到的顯示名 |
| **回覆位址** | 選填，希望回覆走別處時才用 |

<Callout type="info">
  **25 通訊埠不能用。** 我們的託管平台封禁了該通訊埠的對外連線，請用 587 或 465。
</Callout>

### 各服務供應商怎麼填

<Tabs items={['Resend', '企業自建電子郵件', 'Gmail（SMTP 備用）']}>
  <Tab value="Resend">
    | 欄位 | 值 |
    | --- | --- |
    | SMTP 伺服器 | `smtp.resend.com` |
    | 通訊埠 | `587 (STARTTLS)` |
    | 使用者名稱 | `resend` —— 就是這個詞本身 |
    | 密碼 | 一個 Resend API key（`re_…`） |
    | 寄件者位址 | 你在 Resend 裡已驗證網域下的任意位址 |

    如果你希望通知從**自己的品牌網域**發出、而不是某個私人電子郵件，這是最省事的選擇，也沒有 Gmail 那種每日上限。
  </Tab>

  <Tab value="企業自建電子郵件">
    向管理郵件系統的同事要 **SMTP 主機名稱、通訊埠和憑據**。優先用 587 + STARTTLS，只有 465 可選時才用 465。

    兩個常見坑：

    - 使用者名稱往往是**完整電子郵件位址**，不是 `@` 前面那截。
    - **寄件者位址必須屬於你自己的網域**。多數企業郵件伺服器會拒絕代發聲稱來自其他網域的信。
  </Tab>

  <Tab value="Gmail（SMTP 備用）">
    優先用上面的**連接 Gmail**——它不需要應用專用密碼。只有無法使用 Google 連接時才走 SMTP。

    | 欄位 | 值 |
    | --- | --- |
    | SMTP 伺服器 | `smtp.gmail.com` |
    | 通訊埠 | `587 (STARTTLS)` |
    | 使用者名稱 | 完整的 Gmail 位址 |
    | 密碼 | **16 位應用專用密碼** |
    | 寄件者位址 | **同一個** Gmail 位址，或該帳號裡已驗證的「以此身分傳送」別名 |

    去 [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords) 產生應用專用密碼。它只顯示一次，格式是四組四位 —— 貼上前**把空格去掉**。

    <Callout type="warning">
      帳號密碼是不行的。Google 已經關閉了郵件客戶端的密碼登入，只能用應用專用密碼 —— 而應用專用密碼只有在**兩步驟驗證已開啟**時才存在。
    </Callout>

    如果那個頁面顯示「你要找的設定不適用於你的帳戶」，原因是三者之一：兩步驟驗證沒開；這是 Google Workspace 帳號且管理員停用了應用專用密碼；或者帳號加入了進階保護計畫（會直接停用這個功能）。

    另外 Gmail 有傳送上限：個人帳號約**每天 500 個收件人**，Workspace 約 **2000**。對團隊通知完全夠用，但不適合群發。
  </Tab>
</Tabs>

## 儲存並驗證

這一節和下一節適用於 SMTP 伺服器；Gmail 連接由 Google 的登入授權完成驗證。

<Steps>
### 填好欄位，點「儲存並驗證」

儲存和驗證是同一個動作，所以不會出現「存下來了但沒測過」的中間狀態。

### 去收件匣找那封測試郵件

<Callout type="warning">
  測試郵件發往**你自己的 RooQuiz 帳號電子郵件** —— 也就是你目前登入用的那個，**不是**你剛填的寄件者位址。如果沒收到，先查那個電子郵件和它的垃圾郵件資料夾，別急著改設定。
</Callout>

### 確認狀態顯示「已驗證」
</Steps>

「已驗證」的含義是：你的 SMTP 伺服器接收了這封信並回傳了成功碼。這**不等於送達** —— SMTP 伺服器是先收下、再往外轉投，所以信件之後仍可能被判垃圾或被退回。如果驗證通過卻沒收到，問題在收件一側：先看垃圾郵件資料夾，再去寄件信箱裡找退信。

## 驗證失敗時

頁面上會**原樣顯示你的 SMTP 伺服器回傳的錯誤**，刻意不做轉述，方便你直接照著處理。常見的幾種：

| 錯誤 | 含義 |
| --- | --- |
| `535 Username and Password not accepted` | 憑據不對。Gmail 的情況通常是用了帳號密碼，或者應用專用密碼裡的空格沒去掉 |
| `553 Sender address rejected: not owned by user` | 寄件者位址不在這台伺服器允許代發的範圍裡。改成該帳號真正擁有的電子郵件或別名 |
| `550 relay not permitted` | 伺服器完全不為你轉投 —— 一般是使用者名稱填錯，或該電子郵件沒開 SMTP 權限 |
| 逾時 / 連線失敗 | 主機名稱或通訊埠不對，或者伺服器不接受來自外部網路的連線 |

## 一些細節

- 密碼儲存後**不再回顯**。修改其他欄位時把它留空，已儲存的密碼不會被動。
- 改動伺服器、通訊埠、使用者名稱、密碼或寄件者位址，狀態會退回**未驗證**，直到下一次驗證成功。
- 儲存與驗證有**頻率限制**，每個團隊每小時只能試幾次 —— 每一次都會真的連線到你的伺服器、真的發出一封信。
- **移除**寄信服務會刪掉已儲存的密碼。改設定不需要先移除，直接覆蓋儲存即可。只要還有**啟用中**的郵件連接器在使用這個寄信服務，移除會被拒絕 —— 免得你把自己的投遞靜默弄壞。
- 如果之後某次投遞永久失敗（憑據失效、寄件者位址被拒），狀態會變成**驗證失敗**，郵件連接器會停止投遞直到你修好。單個收件人位址失效**不會**導致這種情況，那只會讓那一封信失敗。
