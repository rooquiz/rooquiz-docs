title: 메일 발송 서비스(SMTP)
description: '팀 자체 SMTP 발송 서비스를 설정하면 이메일 커넥터가 플랫폼 발송 한도 없이 내 주소로 메일을 보냅니다. 설정 위치와 입력 항목, Gmail·Resend·회사 메일 서버별 설정 방법, 저장과 확인 과정, 확인 실패 시 오류 해석, 그리고 발송 서비스가 없을 때 무엇이 동작하지 않는지 설명합니다.'
---

[이메일 커넥터](/ko/connectors/channels)는 **직접 준비한 SMTP 서버**로 발송하며, RooQuiz가 메일을 중계하지 않습니다. 따라서 알림은 내 주소에서 발송되고 플랫폼 발송 한도도 없습니다.

팀마다 한 번 **설정 → 조직 → 메일 발송**에서 설정합니다. 팀의 모든 이메일 커넥터가 이 설정을 사용합니다.

<Callout type="warning">
  **확인된** 발송 서비스가 없으면 이메일 커넥터를 저장할 수는 있지만 실제로 발송되지 않습니다. 커넥터 카드에 빨간색 "발송 서비스 없음" 태그가 표시됩니다.
</Callout>

## 입력 항목

| 항목 | 설명 |
| --- | --- |
| **SMTP 서버** | 메일 제공업체의 호스트 이름. 예: `smtp.gmail.com` |
| **포트** | `587`(STARTTLS), `465`(SSL/TLS) 또는 `2525` |
| **사용자 이름** | 보통 전체 이메일 주소입니다. 일부 제공업체는 고정된 문자열을 사용합니다 |
| **비밀번호** | SMTP 비밀번호 또는 API 키. 나중에 편집할 때 비워 두면 저장된 값이 유지됩니다 |
| **발신 주소** | SMTP 서버가 발신자로 사용할 수 있도록 허용된 주소여야 합니다 |
| **발신자 이름** | 수신자에게 표시되는 이름 |
| **회신 주소** | 선택 사항. 회신을 다른 곳으로 받고 싶을 때 사용합니다 |

<Callout type="info">
  **25번 포트는 사용할 수 없습니다.** 호스팅 플랫폼이 이 포트의 외부 연결을 차단합니다. 587 또는 465를 사용하세요.
</Callout>

## 제공업체별 설정

<Tabs items={['Gmail', 'Resend', '회사 메일 서버']}>
  <Tab value="Gmail">
    | 항목 | 값 |
    | --- | --- |
    | SMTP 서버 | `smtp.gmail.com` |
    | 포트 | `587 (STARTTLS)` |
    | 사용자 이름 | 전체 Gmail 주소 |
    | 비밀번호 | **16자리 앱 비밀번호** |
    | 발신 주소 | **같은** Gmail 주소 또는 확인된 "다른 주소에서 메일 보내기" 별칭 |

    앱 비밀번호는 [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords)에서 만듭니다. 네 글자씩 네 묶음으로 한 번만 표시되며, 붙여 넣기 전에 **공백을 제거하세요**.

    <Callout type="warning">
      일반 계정 비밀번호로는 동작하지 않습니다. Google이 메일 클라이언트의 비밀번호 로그인을 막았기 때문에 앱 비밀번호가 필요하며, 앱 비밀번호는 **2단계 인증**을 켠 경우에만 만들 수 있습니다.
    </Callout>

    해당 페이지에 *"The setting you are looking for is not available for your account"*라고 표시된다면 다음 중 하나에 해당합니다. 2단계 인증이 꺼져 있거나, 관리자가 앱 비밀번호를 비활성화한 Google Workspace 계정이거나, 앱 비밀번호를 원천 차단하는 고급 보호 프로그램에 등록된 계정입니다.

    Gmail은 발송량도 제한합니다. 개인 계정은 하루 약 **500명**, Workspace는 **2,000명**의 수신자까지입니다. 팀 알림에는 충분하지만 대량 메일에는 적합하지 않습니다.
  </Tab>

  <Tab value="Resend">
    | 항목 | 값 |
    | --- | --- |
    | SMTP 서버 | `smtp.resend.com` |
    | 포트 | `587 (STARTTLS)` |
    | 사용자 이름 | `resend` — 이 단어 그대로 |
    | 비밀번호 | Resend API 키(`re_…`) |
    | 발신 주소 | Resend에서 확인한 도메인의 아무 주소 |

    개인 메일함이 아니라 **자체 브랜드 도메인**에서 알림을 보내고 싶다면 가장 쉬운 방법이며, Gmail과 같은 일일 한도도 없습니다.
  </Tab>

  <Tab value="회사 메일 서버">
    메일 서버를 운영하는 담당자에게 **SMTP 호스트 이름, 포트, 인증 정보**를 문의하세요. STARTTLS를 사용하는 587 포트를 우선 사용하고, 465만 제공된다면 465를 사용하세요.

    자주 실수하는 부분이 두 가지 있습니다.

    - 사용자 이름은 `@` 앞부분이 아니라 **전체 메일 주소**인 경우가 많습니다.
    - **발신 주소는 자사 도메인에 속해야 합니다.** 대부분의 회사 서버는 다른 곳에서 보낸 것처럼 표시된 메일의 중계를 거부합니다.
  </Tab>
</Tabs>

## 저장 및 확인

<Steps>
### 항목을 입력하고 "저장하고 확인" 클릭

저장과 확인이 하나의 동작이므로, 저장만 되고 테스트되지 않은 구성이 남는 일이 없습니다.

### 받은편지함에서 테스트 메일 확인

<Callout type="warning">
  테스트 메일은 방금 설정한 발신 주소가 **아니라**, 현재 로그인한 **본인의 RooQuiz 계정 주소**로 발송됩니다. 메일이 오지 않으면 설정을 바꾸기 전에 그 받은편지함과 스팸함부터 확인하세요.
</Callout>

### 상태가 "확인됨"인지 확인
</Steps>

**확인됨**은 SMTP 서버가 메일을 접수하고 성공 코드를 반환했다는 뜻입니다. 이는 전달 완료와 같지 않습니다. SMTP 서버는 먼저 메일을 접수한 뒤 나중에 전달하므로, 그 후에도 스팸으로 걸러지거나 반송될 수 있습니다. 확인에는 성공했는데 메일이 오지 않는다면 수신 측 문제입니다. 먼저 스팸함을 확인하고, 그다음 발송에 사용하는 메일함에서 반송 메일을 찾아보세요.

## 확인에 실패했을 때

페이지에는 **SMTP 서버가 반환한 오류가 그대로** 표시됩니다. 바로 조치할 수 있도록 일부러 수정하지 않은 것입니다. 자주 보는 오류는 다음과 같습니다.

| 오류 | 의미 |
| --- | --- |
| `535 Username and Password not accepted` | 인증 정보가 잘못되었습니다. Gmail이라면 앱 비밀번호 대신 계정 비밀번호를 사용했거나 공백을 남겨 두었습니다 |
| `553 Sender address rejected: not owned by user` | 발신 주소가 이 서버에서 발신자로 사용할 수 없는 주소입니다. 계정이 실제로 소유한 메일함이나 별칭으로 바꾸세요 |
| `550 relay not permitted` | 서버가 중계 자체를 거부합니다. 보통 사용자 이름이 잘못되었거나 메일함에서 SMTP 접근이 활성화되지 않은 경우입니다 |
| 시간 초과 / 연결 실패 | 호스트 이름이나 포트가 잘못되었거나, 서버가 외부 네트워크의 연결을 받지 않습니다 |

## 알아 두면 좋은 점

- 비밀번호는 저장한 후 **다시 표시되지 않습니다.** 다른 항목을 편집할 때 비밀번호 칸을 비워 두면 그대로 유지됩니다.
- 서버, 포트, 사용자 이름, 비밀번호, 발신 주소를 바꾸면 다음 확인에 성공할 때까지 상태가 **미확인**으로 돌아갑니다.
- 저장 및 확인은 팀당 시간당 몇 번으로 **횟수가 제한됩니다.** 매번 실제로 서버에 연결해 메일을 실제로 보내기 때문입니다.
- 발송 서비스를 **삭제**하면 저장된 비밀번호도 삭제됩니다. 설정을 바꾸려고 삭제할 필요는 없으며 덮어써서 저장하면 됩니다. **사용 중인** 이메일 커넥터가 하나라도 있으면 삭제가 거부되므로, 모르는 사이에 발송이 끊기는 일은 없습니다.
- 이후 발송이 영구적으로 실패하면(인증 정보가 더 이상 동작하지 않거나 발신 주소가 거부되는 경우) 상태가 **확인 실패**로 바뀌고, 문제를 해결할 때까지 이메일 커넥터가 발송을 멈춥니다. 수신자 주소 하나가 잘못된 경우에는 이렇게 되지 **않으며**, 해당 메일 한 통만 실패합니다.
